Exchange Online

Alerte CERT-FR sur une faille d'élévation de privilèges dans Microsoft Exchange Server (CVE-2026-96940)

Le CERT-FR a émis le 5 octobre 2026 l'avis CERTFR-2026-AVI-1258 concernant une vulnérabilité critique d'élévation de privilèges affectant Microsoft Exchange Server (éditions 2016, 2019 et Subscription Edition). Un défaut d'autorisation permet à un attaquant distant authentifié sur le réseau d'accéder sans droit aux boîtes aux lettres d'autres utilisateurs du même tenant ou de l'organisation. Si Exchange Online intègre le correctif côté cloud sans action requise, les passerelles et infrastructures hybrides exposées restent particulièrement ciblées pour du vol de correspondance sensible.

Se protéger et détecter : Pour vous protéger, appliquez immédiatement les correctifs cumulatifs sur vos serveurs Exchange hybrides et surveillez les attributions anormales de permissions avec la requête KQL : AuditLogs | where OperationName in ('Add-MailboxPermission', 'Add-RecipientPermission') | project TimeGenerated, InitiatedBy, TargetResources, Result.

Defender for Endpoint

Avis CERT-FR : Risque d'exécution de code arbitraire à distance dans Microsoft 365 Apps (CVE-2026-100208)

Publié le 6 octobre 2026 par l'ANSSI (CERTFR-2026-AVI-1266), cet avis traite d'une faille critique de type RCE (Remote Code Execution) au sein de la suite bureautique Microsoft Office et de Microsoft 365 Apps pour entreprise (32 et 64 bits). La vulnérabilité peut être déclenchée via l'ouverture ou la prévisualisation d'un fichier bureautique spécialement forgé distribué par hameçonnage. Les attaquants exploitent fréquemment ces failles de format pour déposer des implants et exécuter du code dans le contexte de session de l'utilisateur.

Se protéger et détecter : Activez les règles ASR (Attack Surface Reduction) de Defender for Endpoint interdisant la création de processus enfants par les applications Office ('Block all Office applications from creating child processes'). Détectez les anomalies avec la requête KQL : DeviceProcessEvents | where InitiatingProcessFileName in~ ('winword.exe', 'excel.exe', 'powerpnt.exe') and FileName in~ ('powershell.exe', 'cmd.exe', 'wscript.exe', 'cscript.exe').

Entra ID

Industrialisation du vol de jetons par Device Code Phishing via le kit EvilTokens (Storm-2992)

À la suite des opérations de neutralisation récentes, les rapports techniques publiés cette première semaine d'octobre 2026 détaillent l'ampleur des campagnes menées par Storm-2992 via le kit EvilTokens, responsable du piratage de plus de 12 000 boîtes Microsoft 365. Cette plateforme automatise le phishing ciblant le protocole OAuth 2.0 Device Authorization Flow (RFC 8628), détournant un mécanisme légitime pour obtenir des jetons d'accès et d'actualisation sans intercepter les identifiants initiaux. Les attaquants utilisent ensuite des agents IA pour fouiller les boîtes compromises et persister via de faux enregistrements d'appareils.

Se protéger et détecter : Configurez une stratégie d'accès conditionnel (Entra Conditional Access) bloquant le flux d'authentification par code d'appareil ('Device code flow') pour l'ensemble des utilisateurs bureautiques. Pour détecter les tentatives, exécutez la requête KQL : SigninLogs | where AuthenticationProcessingDetails has 'DeviceCode' | project TimeGenerated, UserPrincipalName, AppDisplayName, IPAddress, Location, Status.

Defender for Identity

Alerte conjointe CISA / FBI : Password spraying et ciblage d'infrastructures hybrides Microsoft

Dans un avis conjoint publié le 8 octobre 2026 (AA26-281A), la CISA, le FBI et la NSA alertent sur des campagnes menées par des groupes APT ciblant les organisations gouvernementales et stratégiques. Les acteurs étatiques combinent des attaques massives par pulvérisation de mots de passe (password spraying) contre Microsoft Exchange et les passerelles hybrides, suivies de tentatives de réplication non autorisée de l'Active Directory (DCSync) et de vols de messageries d'entreprises. Ces techniques cherchent à compromettre la synchronisation d'identité entre l'annuaire local et Entra ID.

Se protéger et détecter : Activez les capteurs Microsoft Defender for Identity sur tous les contrôleurs de domaine pour intercepter les alertes de réplication suspecte de compte (DCSync/DRSUAPI) et désactivez l'authentification héritée via Conditional Access. Détectez les patterns de password spray avec la requête KQL : IdentityLogonEvents | where ActionType == 'LogonFailed' and FailureReason == 'InvalidPassword' | summarize FailedAttempts = count(), Targets = dcount(AccountName) by bin(TimeGenerated, 15m), IPAddress | where Targets > 10.
