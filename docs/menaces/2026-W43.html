Entra ID

Compromission d'applications multi-tenants ConnectWise ciblant les environnements Microsoft 365 (Storm-0940)

Entre le 18 et le 21 octobre 2026, Microsoft et l'éditeur ConnectWise ont révélé qu'un acteur étatique (Storm-0940) a détourné des identifiants d'applications d'entreprise multi-tenants (notamment ConnectWise Cloud Backup et Cloud Management) pour s'introduire dans plusieurs centaines de tenants Microsoft 365 sans compromettre de compte utilisateur. En s'appuyant sur le framework automatisé ARTEX, l'attaquant a exploité les autorisations applicatives Microsoft Graph pour siphonner des boîtes aux lettres, des flux Teams et ajouter de nouveaux secrets d'application à des fins de persistance. ConnectWise a désactivé en urgence sept identités d'application et révoqué les certificats associés afin de bloquer les accès non autorisés.

Se protéger et détecter : Désactivez immédiatement l'application d'entreprise dans Entra ID via son ID (ex. 506e08f9-6e9a-4da4-942b-a099a03644ae) sous Propriétés > « Activé pour la connexion des utilisateurs ? = Non ». Détectez les requêtes frauduleuses dans Sentinel avec la requête KQL : `AADServicePrincipalSignInLogs | where ServicePrincipalId == '506e08f9-6e9a-4da4-942b-a099a03644ae' or IPAddress startswith '144.172.64.'`. Enfin, appliquez des règles d'accès conditionnel pour les identités de charge de travail (Workload Identities) afin de restreindre les appels API aux plages d'adresses IP de confiance.

Defender for Office 365

Campagne massive de phishing Microsoft Teams dissimulée dans des invitations de calendrier (.ics)

Documentée à la fin octobre 2026, une campagne de grande envergure totalisant plus de 300 000 courriels malveillants exploite de fausses invitations à des réunions Microsoft Teams distribuées sous forme de fichiers .ics. Les messages imitent les notifications internes légitimes avec un faux lien « Rejoindre la réunion » redirigeant les collaborateurs vers des pages de connexion Microsoft 365 clonées afin d'intercepter identifiants et jetons. Cette méthode permet aux cybercriminels de tromper la vigilance des utilisateurs tout en contournant les passerelles de messagerie qui n'inspectent pas en profondeur les métadonnées des pièces jointes de type calendrier.

Se protéger et détecter : Configurez Microsoft Defender for Office 365 pour appliquer l'analyse Safe Attachments en mode blocage dynamique sur les pièces jointes .ics ainsi que la réécriture Safe Links sur les URL qu'elles contiennent. Recherchez les messages suspects avec cette requête KQL : `EmailAttachmentInfo | where FileType has 'ics' | join EmailUrlInfo on NetworkMessageId | where UrlDomain !has 'microsoft.com' and (Url has 'teams' or Url has 'meeting') | project DeliveryTime, RecipientEmailAddress, SenderFromAddress, Url`.

SharePoint

Alerte CERT-FR sur une faille d'élévation de privilèges dans Microsoft SharePoint (CVE-2026-88164)

Dans son bulletin hebdomadaire CERTFR-2026-ACT-044 publié le 19 octobre 2026, le CERT-FR a mis en évidence une vulnérabilité critique d'élévation de privilèges référencée CVE-2026-88164 (score CVSS 8,8) ciblant Microsoft SharePoint Server Subscription Edition. Un attaquant distant déjà doté d'un compte avec des droits restreints sur l'organisation peut exploiter cette faille pour contourner les mécanismes d'autorisation et s'octroyer des privilèges administrateur sur la ferme SharePoint. Bien que distincte des précédentes failles RCE publiques, cette vulnérabilité expose les données documentaires critiques et peut servir de levier pour pivoter vers l'Active Directory.

Se protéger et détecter : Appliquez immédiatement le correctif vers la build 16.0.20326.20190 ou supérieure de SharePoint Server Subscription Edition. Surveillez dans Microsoft Defender for Endpoint les comportements inhabituels ou injections de processus issus de `w3wp.exe` liés aux pools d'applications SharePoint (`DeviceProcessEvents | where ProcessCommandLine has 'w3wp.exe' and InitiatingProcessFileName =~ 'w3wp.exe'`).

Exchange Online

Blocage des flux OWA et rupture de liaisons RPC sur Exchange suite aux correctifs Windows d'octobre 2026

Entre le 16 et le 20 octobre 2026, Microsoft a confirmé un dysfonctionnement majeur affectant les serveurs de messagerie Exchange Server connectés à Windows Server 2019 et ultérieur. La mise à jour cumulative Windows d'octobre a introduit une limite stricte de 512 appels simultanés sur l'Endpoint Mapper RPC, saturant les traitements sous forte charge et provoquant des échecs massifs de connexion sur Outlook on the Web (erreur MapiExceptionMdbOffline / Event ID 1006) ainsi que le blocage des courriels sortants. Cette dégradation perturbe particulièrement les flux de synchronisation et de transport dans les organisations opérant en environnement hybride avec Exchange Online.

Se protéger et détecter : Ne désinstallez pas les correctifs de sécurité : appliquez la directive Microsoft en modifiant la clé de registre `HKLM\SOFTWARE\Microsoft\Rpc` pour rehausser la limite mémoire de l'Endpoint Mapper sur les serveurs Exchange. Surveillez l'apparition de l'Event ID 1006 dans le journal Application via la commande PowerShell `Get-WinEvent -FilterHashtable @{LogName='Application'; ProviderName='MSExchangeIS'; Id=1006}` afin de détecter immédiatement la rupture des boîtes aux lettres.

Conditional Access

Usurpation de marque : Microsoft concentre un tiers des attaques mondiales de phishing

Le rapport de Check Point Research sur les tendances de phishing publié mi-octobre 2026 révèle que Microsoft demeure la marque la plus usurpée au monde, représentant 33 % de l'ensemble des tentatives recensées (en hausse de 10 points). Les cybercriminels ciblent prioritairement la stack Microsoft car la compromission d'un compte professionnel ouvre un accès direct aux outils collaboratifs (Teams, OneDrive, SharePoint) et facilite les fraudes au président (BEC) ou le rebond interne. La recrudescence des leurres simulant les alertes de facturation et les portails de connexion Microsoft accentue la pression sur les identités d'entreprise.

Se protéger et détecter : Déployez une stratégie d'accès conditionnel exigeant une force d'authentification résistante au phishing (Phishing-resistant MFA : clés FIDO2 ou Windows Hello for Business) pour tous les accès aux applications cloud Microsoft 365. Détectez les connexions anormales résultant d'identifiants dérobés avec la requête KQL : `SigninLogs | where AuthenticationRequirement == 'multiFactorAuthentication' | where RiskLevelDuringSignIn in ('high', 'medium') | project TimeGenerated, UserPrincipalName, IPAddress, Location, RiskDetails`.
